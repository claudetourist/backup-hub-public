## R0.5 (22 Nov 2026): start-up no longer blocks on the database (found by `npm run bench --db <real copy>`: schema 19 copy, Home never usable, 2 s stall)
- Migrations run on a worker thread, before the main connection opens: `db/migrate.ts` `migrateFile(file)` (own read-write connection, same migrations, one transaction each, WAL truncated after) and `readSchemaVersion(file)` (read-only, to know whether there is anything to do); `query/queryWorker.ts` answers the one-off op `migrate`; `query/queryService.ts` `migrateInWorker(workerPath, file)` (a worker started for that one request; `quickCheckInWorker` now shares its `runOneShot`). Null reply = worker could not start: the main thread migrates as before and logs a warning.
- `db/index.ts` `initDatabaseAsync(..., onChecking({bytes}), now, migrate?)`: order is quick_check (if needed) on its worker, then (only if it passed, or none was needed) migration on a worker (`migrate.run`, `migrate.onStart`), then the main connection opens (nothing left to migrate). A file that fails quick_check is never migrated or opened for writing. Without `migrate` (tests) migrations still run on the main thread inside `openChecked`.
- The safety check stays BEFORE any write, so it still blocks the app while it runs (about 40 s on 1.5 GB, only after a crash or no full check for 7 days). It is not made non-blocking: a read-only check beside a writing app cannot stop writes to a file that then fails. What changed is what Home says meanwhile.
- Start-up state: `shared/startup.ts` (`StartupStatus` {phase opening/checking/updating, elapsedMs, estimateMs}, `estimateCheckMs(bytes)` at 30 MB/s), IPC `app.startupStatus` now returns it (main.ts `setStartupPhase`); renderer `startupModel.ts` (words and bar, pure), `components/StartupNotice.tsx`, `App.tsx` shows the notice instead of the screens (mounted, `.screen-slot--waiting`) until data is ready. `renderer/bench.ts` waits up to 200 s for Home (a copy that needs its check or update).
